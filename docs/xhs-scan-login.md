# 小红书扫码登录

管理员点击工作台顶部二维码按钮 →「小红书扫码登录」，项目在运行 Web 服务的电脑上打开独立的 Microsoft Edge 窗口，进入 `https://www.xiaohongshu.com/explore`，出现登录按钮时自动打开官方登录面板。使用小红书 App 扫码并在手机确认后，项目自动保存登录状态，供下载、商品读取和低粉爆款采集使用。

该按钮打开官方网页，由小红书处理扫码、手机确认和可能出现的验证。它不是小红书 OAuth 应用授权，也没有复制二维码到项目内。远程访问本项目时，登录窗口仍出现在服务所在电脑，需要在那台电脑上完成操作。

## 自动保存条件

- 浏览器必须取得适用于采集 API 的 `a1` 和 `web_session`。
- 官方 `user/me` 响应必须确认 `guest=false` 且存在 `user_id`；仅有 Cookie 或看到二维码不算登录成功。
- 优先使用官方页面自身返回的登录状态；必要时使用当前 Cookie 请求同一官方账号状态接口核验。同一组 a1/web_session 不重复探测。
- 验证后通过项目现有 `save_cookie` 更新运行中后端及本地配置；查询接口、页面和日志不返回 Cookie 值。
- 成功后关闭独立登录窗口，页面提示「已自动保存」，可直接点击「立即采集」。不额外自动发起采集或模型生成。

只读取本次独立登录上下文中适用于 `edith.xiaohongshu.com` 的根路径 Cookie，不读取日常浏览器的其他网站登录信息。浏览器上下文关闭后，仅保留项目原有 Cookie 配置。

## 等待、取消和异常

登录期限为 3 分钟。取消、关闭浏览器或超时后不保存新 Cookie；已有配置保留。扫码任务进行中禁止第二次启动和手动覆盖，取消与自动保存按顺序执行。服务退出会通知登录任务停止。

平台返回 IP 风险提示（如 `300012`）时，页面显示原含义，不记录为登录成功。需要先按小红书官方页面提示恢复正常访问，再重新扫码；程序不自动处理平台验证。

「手动填写 Cookie」收在高级选项中。关闭弹窗不会发出空 Cookie 保存请求，只有点击「手动保存」才更新或清除。

## 每日采集

现有每日任务读取运行中的最新设置，因此扫码保存后不需要复制 Cookie 或重启服务。当前定时为北京时间 09:00，关键词为潮玩、家居、女生精致小物。若当天已有失败记录，完成登录后点击「立即采集」补采；之后按原定时运行。

## 依赖与接口

浏览器依赖复用 `requirements-product-browser.txt` 的 Playwright。Windows 使用已安装的 Microsoft Edge，需在有桌面的会话运行。

- `GET /api/xhs/login`：管理员查看不含 Cookie 的任务状态。
- `POST /api/xhs/login`：管理员及 CSRF 校验后启动窗口，返回 202。
- `DELETE /api/xhs/login`：管理员及 CSRF 校验后取消任务。
- `PUT /api/settings/cookie`：原手动保存入口，增加与扫码任务的并发保护。

自动化测试使用隔离账号与模拟手机确认，覆盖 Cookie 域过滤、游客排除、账号核验、取消后迟到结果、重复启动、保存失败脱敏、权限、超时和实际工作台交互。真实网站验证结果另见 `output/xhs-scan-login/VERIFICATION.txt`；没有将模拟手机确认当作真实扫码登录成功。
